# Dualyrics v2 design system

Status: implemented in v2 (settings window, template model, renderer, presets). Where the implementation differs from this text, the reason is in "Implementation notes" at the end.

This document covers three things:

1. The design tokens and layout of the v2 settings window (customtkinter).
2. The subtitle **template** model: one JSON document that describes everything about how the overlay looks.
3. Eight built-in preset templates with exact values, all checked for contrast over bright and dark scenes.

Who it is for: people who keep Dualyrics on top of a game (God of War Ragnarok, for example), a film or a music player (Spotify, Spotube, YouTube Music). Many of them read Persian, but the app is public and multilingual, so every visible string lives in `dualyrics/i18n.py` (English and Persian), and every layout mirrors for right-to-left languages.

- `coral` is a brand colour, not an error colour. Destructive actions always use `danger` plus a label.

### 1.2 Typography

**Families** (the first installed family wins; checked with `tkinter.font.families()` at start-up):

| Role | Latin UI (`ui_language = en`, others) | Persian UI (`ui_language = fa`) |
|---|---|---|
| UI text | `Segoe UI Variable Text` → `Segoe UI` → `Arial` | `Vazirmatn` → `Segoe UI` → `Tahoma` |
| Headings | `Segoe UI Variable Display` → `Segoe UI` | `Vazirmatn` → `Segoe UI` → `Tahoma` |
| Numbers, hotkeys, offsets, keys | `Cascadia Mono` → `Consolas` | same as Latin (digits stay readable) |

Notes:

- Segoe UI Variable ships with Windows 11; Windows 10 falls back to Segoe UI.
- Vazirmatn is not part of Windows. It is licensed under the SIL Open Font License 1.1, so v2 should bundle `Vazirmatn[wght].ttf` (variable) in `dualyrics/assets/fonts/` together with its licence file and load it for this process only with `AddFontResourceExW(path, FR_PRIVATE, 0)`. Then every user gets it without installing anything. Static installs show up in Tk as separate families (`Vazirmatn`, `Vazirmatn Medium`, `Vazirmatn ExtraBold`), so the resolver maps a weight to the matching family name when it exists.
- Tk only knows `normal` and `bold`. Weights 500 and 600 are reached by choosing the named family (`Segoe UI Semibold`, `Vazirmatn Medium`).
- Persian text in a mixed sentence (for example "کلید Gemini") keeps the existing RLE/PDF embedding from `i18n.rtl_embed`.

**Type scale** (customtkinter `CTkFont(size=…)`, logical pixels at 100% scaling):

| Token | Size | Weight | Used for |
|---|---:|---|---|
| `type.display` | 28 | 700 | App name on About |
| `type.title` | 20 | 600 | Section title at the top of the content column |
| `type.subtitle` | 16 | 600 | Group header ("Text lines", "Box", "Motion") |

### 1.7 Live preview pane

- Renders with the real overlay renderer (same code path, same template), scaled to fit 348 × 196 at 16:9, so what you see is exactly what the overlay draws.
- **Backdrops** (generated with Pillow at start-up, no copyrighted screenshots): `Dark scene` (`#05070D` to `#1B2333` gradient with faint noise), `Bright scene` (`#F5F7FA` to `#CFE3F5`, sky and snow), `Busy game scene` (high-frequency noise, mixed hues and white specks, the worst case for readability), `Checker` (shows transparency). A fifth option, `Desktop`, uses a one-off screenshot of the area under the overlay when the user clicks it (kept in memory only).
- **Sample text**: `Current song` (the line playing now) or a built-in pair per direction, for example "I still hear your voice when the night is quiet" with "هنوز وقتی شب آرام است صدایت را می‌شنوم". The speaker sample is "NARRATOR". Arabic, Hebrew and CJK samples come from `langs.py` target language.
- **Animation preview**: a play button runs the enter, karaoke sweep and exit once. It respects reduced motion like the overlay.
- **Contrast badge** per visible line, computed against the current backdrop (see 3.3 for the method).
- Updates are debounced to 60 ms while a slider moves, so dragging stays smooth.

### 1.8 Implementing the tokens in customtkinter

- `dualyrics/ui/tokens.py`: plain Python constants, each a `(light, dark)` tuple, plus the type scale and spacing scale. One import for every widget file.
- `dualyrics/assets/theme/dualyrics.json`: a customtkinter theme file generated from the tokens (buttons, frames, entries, switches, sliders, option menus, scrollbars), loaded with `ctk.set_default_color_theme(path)` instead of the built-in `"blue"`.
- New setting `ui_theme`: `system` (default), `dark`, `light`, passed to `ctk.set_appearance_mode`. The overlay does not follow the UI theme; it follows its template.
- Fonts: set `ThemeManager.theme["CTkFont"]["family"]` from the resolver in 1.2 (today it is hard-coded to `Segoe UI`).

### 1.9 Accessibility checklist (settings window)

- [ ] All text pairs in 1.1 meet 4.5:1, controls and focus meet 3:1, in both themes.
- [ ] Every control is reachable and usable with the keyboard; the focus ring is always visible.
- [ ] Hit areas are at least 24 × 24 px; normal controls are 32 px high.
- [ ] Labels are always visible (no placeholder-only fields); help text sits under the control.
- [ ] Meaning never depends on colour alone (icons and words with every status colour).
- [ ] Persian UI mirrors layout, alignment and Tab order; numbers and Latin names inside Persian text keep their order.
- [ ] Windows "Animation effects" off ⇒ no slides anywhere (preview and overlay).
- [ ] Windows text scaling and 100 to 200% DPI keep the layout intact (customtkinter scaling).

## 2. Subtitle template model

### 2.1 Concepts

- A **template** describes how the overlay looks: fonts, colours, effects, box, line order, karaoke and motion. It does **not** hold where the overlay is (position, monitor, lock, click-through stay in `settings.json`, per monitor, as in v1). A template can only *suggest* those through `hints`, and the app asks before applying them.
- **Built-in templates** ship read-only inside the package (`dualyrics/templates/builtin/<id>.json`). Editing one creates a copy (`based_on` = the preset id) and switches to it, so presets always stay intact and "Reset to preset" is always possible.
- **User templates** live in `%APPDATA%\Dualyrics\templates\<id>.json`. Import and export use the same file format, so people can share looks.
- `settings.json` gets one new key, `template` (the active id, default `cinema` for new installs; upgrades get the migrated v1 look, see 2.5).
- Built-in names and descriptions are shown from `i18n.py` (`tpl_<id>`, `tpl_<id>_desc`). The `name` and `description` objects inside the JSON are the fallback and the only source for user templates, which can carry any locale.
- At runtime a template is validated the same way `settings.validate()` works: unknown keys dropped, out-of-range values clamped, bad values replaced by the preset or Cinema value. The JSON Schema in 2.6 is the reference and is used by tests and by Import (to tell the user what is wrong); the app does not need `jsonschema` at runtime.

### 2.2 Property reference

All lengths are pixels at the reference height (1080 px tall screen), then multiplied by the scale factor (2.3).

**Per line** (`lines.original`, `lines.translation`, `lines.next`, `lines.speaker`):

| Property | Type / range | Meaning |
|---|---|---|
| `visible` | bool | Draw this line at all |
| `font.latin` | list of family names | Used when the line is left-to-right. First installed family wins; `"auto"` = built-in stack |
| `font.rtl` | list of family names | Used when the line is right-to-left (Persian, Arabic, Hebrew, Urdu, Kurdish Sorani, Pashto) |
| `font.size` | 8 to 120 | Font size |
| `font.weight` | 100 to 900, steps of 100 | Nearest available weight of that family |
| `font.italic` | bool | Never applied to right-to-left scripts (Persian has no true italic) |
| `color` | `#RRGGBB` | Solid fill, also the fallback when a gradient cannot be drawn |
| `gradient` | null or `{angle, stops[2..4]}` | Fill gradient across each line's own box; 0° = left to right, 90° = top to bottom |
| `opacity` | 0 to 1 | Opacity of the fill, outline and shadow of this line |
| `outline.width` / `color` / `opacity` | 0 to 8, colour, 0 to 1 | Round-joined stroke around the glyphs, drawn under the fill |
| `shadow` | list of up to 4 `{x, y, blur, color, opacity}` | Drawn bottom-up under the outline. Offset 0 + blur = glow |
| `letter_spacing` | -2 to 12 | Extra space between characters. Ignored for joined scripts (it would break letter joining) |
| `line_height` | 0.8 to 2.5 | Multiplier of the font's line height for wrapped lines |
| `max_lines` | 1 to 8 | Wrap limit; overflow ends in an ellipsis (…) at the logical end |
| `uppercase` | bool | Uppercase for scripts with case; no effect on Persian, Arabic, CJK |
| `format` (speaker only) | string with `{name}` | For example `"{name}:"` or `"[{name}]"` |
| `placement` (speaker only) | `inline` / `above` | Before the original line, or on its own line above it |

**Container** (`container`):

| Property | Type / range | Meaning |
|---|---|---|
| `background.color` / `opacity` | colour, 0 to 1 | Box fill. Opacity 0 = no box (text only). Unlike v1, opacity no longer fades the text |
| `background.gradient` | null or gradient | Box gradient; `color` stays the fallback |
| `blur.mode` | `none` / `simulated` / `acrylic` | "Frosted" look. `simulated` = tint + `sheen` + `noise` only; `acrylic` = real blur-behind when Windows allows it, else simulated |
| `blur.strength` / `noise` / `sheen` | 0 to 40, 0 to 0.1, 0 to 0.3 | Blur radius (acrylic), grain amount, top highlight strength |
| `padding.x` / `padding.y` | 0 to 80 | Inner space |
| `corner_radius` | 0 to 48 | Box corners |
| `border.width` / `color` / `opacity` | 0 to 6, colour, 0 to 1 | Box rim |
| `shadow` | null or one shadow | Drop shadow of the box |
| `width.unit` / `value` | `px` / `percent`, 10 to 4000 | Box width in px, or % of the monitor's work-area width |
| `width.fit_content` | bool | The box hugs the longest line; `value` becomes the maximum |
| `width.min_px` | 0 to 2000 | Lower limit when hugging, so short lines do not make a tiny box |
| `align` | `center` / `start` / `end` / `left` / `right` | `start` and `end` follow each line's direction when `layout.mirror_for_rtl` is true |
| `line_gap` | 0 to 48 | Space between original and translation |
| `group_gap` | 0 to 64 | Extra space before the next line |

**Layout, karaoke, motion, timing, hints:**

| Property | Type / range | Meaning |
|---|---|---|
| `layout.translation_position` | `below` / `above` | Translation under or over the original. Order is always speaker (above), the pair, then next |
| `layout.mirror_for_rtl` | bool | `start`/`end` alignment follows the direction of each line |
| `karaoke.enabled` | bool | Highlight the line being sung |
| `karaoke.mode` | `line` / `sweep` / `word` | `line`: the active line changes colour when it starts. `sweep`: the highlight fills the line from start to end over the line's duration (until the next timestamp). `word`: uses per-word timestamps of enhanced LRC when present, else sweep |
| `karaoke.applies_to` | `original` / `translation` / `both` | Which line gets the highlight |
| `karaoke.highlight_color` / `highlight_gradient` | colour, null or gradient | Colour of the sung part |
| `karaoke.inactive_opacity` | 0 to 1 | Opacity of the part not yet sung (sweep, word) or of the line before it starts (line) |
| `karaoke.glow` | null or shadow | Extra glow on the sung part only, so sung/unsung differ by more than hue |
| `animation.enter` / `exit` | `none`, `fade`, `slide_up`, `slide_down`, `fade_slide_up`, `fade_slide_down` | Transition when a line appears or leaves |
| `animation.duration_ms` / `exit_duration_ms` | 0 to 1000 | Exit should be shorter than enter (about 60 to 70%) |
| `animation.slide_px` | 0 to 48 | Slide distance |
| `animation.easing` | `linear`, `ease_out`, `ease_in_out`, `ease_out_back` | Timing curve |
| `animation.reduced_motion` | `respect` / `ignore` | `respect`: when Windows animation effects are off, slides become fades of at most 120 ms |
| `timing.min_display_ms` | 0 to 10000 | A line stays at least this long, even if the next timestamp comes sooner (fast rap lines). The next line then appears late but in sync from there on; lines are never skipped |
| `hints.placement` | `keep` / `bottom` / `top` / `center` | Suggested position preset |
| `hints.click_through` / `locked` | bool or null | Suggested window behaviour; null = no opinion |

### 2.3 Rendering rules

1. **Scale**: `screen` (all presets) multiplies every length by `monitor height / reference_height`, so text has the same share of the screen on 1080p, 1440p and 4K. `dpi` multiplies by the monitor DPI scale (v1 behaviour). `fixed` uses the numbers as written. The mouse-wheel size gesture of v1 becomes a user multiplier (50 to 200%) stored in settings, applied on top of any template.
2. **Order**: `speaker` (if `placement = above`), then original and translation in the order given by `translation_position`, then `next` after `group_gap`.
3. **Direction**: each line's direction comes from its own text (`langs.is_rtl_text`), so an English original and a Persian translation each get the right font stack, wrapping and alignment. RTL lines are pre-wrapped and embedded in RLE…PDF as in v1.
4. **Empty states**: when there is no lyric line, the original slot shows `♪`; status messages ("Looking for lyrics…") use the `next` style.
5. **Plain (unsynced) lyrics** keep the scrolling list of v1, drawn with the original and translation styles, with `container` used for the scroll box.
6. **Min display**: see `timing.min_display_ms`. Karaoke sweep time is measured from the real timestamps, never from the extended display time.

### 2.4 Renderer constraints (what v2 needs under the hood)

v1 draws on a Tk canvas: the outline is stamped as many copies of the text, the shadow is one hard offset copy, and text-only mode uses a colour key (`-transparentcolor`), which is 1-bit transparency. Gradients, blurred shadows, glow, letter spacing and frosted boxes cannot be drawn that way, and soft edges would show coloured fringes against the key colour.

Recommended v2 renderer:

- Draw each frame into a 32-bit premultiplied BGRA bitmap and show it with `UpdateLayeredWindow(..., ULW_ALPHA)` on a layered window. That gives true per-pixel alpha (soft shadows over any game), and `WS_EX_TRANSPARENT` keeps click-through working as in v1.
- **Text shaping must come from Windows.** The Pillow in the project venv (13.0.0) reports `PIL.features.check("raqm") == False`, so Pillow alone would draw Persian letters unjoined and in the wrong order. Draw the glyphs with GDI (`ExtTextOutW`/`DrawTextW`, which shape through Uniscribe) into a DIB as a grayscale coverage mask (white on black, `ANTIALIASED_QUALITY`, ClearType off), then do everything else with Pillow: fill (solid or gradient through the mask), outline (dilate the mask, `ImageFilter.MaxFilter`, or GDI `StrokePath`), shadow and glow (`GaussianBlur` of the mask), box, and compositing.
- Letter spacing uses `SetTextCharacterExtra`, only for scripts that do not join.
- Cache each rendered line by `(text, style hash, scale)`. Karaoke sweep is then just two cached bitmaps with a moving clip, cheap enough for 60 fps. Draw at 60 fps only while something animates; at rest nothing is redrawn.
- `acrylic` uses the undocumented `SetWindowCompositionAttribute` blur-behind accent. It must be tested together with per-pixel alpha; if they conflict, fall back to `simulated` (the schema already defines the fallback).
- No desktop window can be drawn over a game in **exclusive** fullscreen. The Game HUD preset (and the Overlay section) should say: use the game's Borderless or Windowed fullscreen mode.
- Optional later: an "adaptive backdrop" setting that samples the brightness behind the overlay twice a second (`BitBlt` with the overlay excluded through `SetWindowDisplayAffinity(WDA_EXCLUDEFROMCAPTURE)`, Windows 10 2004+) and raises box opacity on bright scenes. Side effect: that flag also hides the overlay from screen recorders and OBS, so it must be opt-in and explained.

### 2.5 Migration from v1 settings

On first start of v2, the current v1 appearance keys become one user template, `my-style` ("My style (v1)" / "سبک من (نسخه ۱)"), which becomes active. Nothing visible changes for existing users.

| v1 key | v2 template field |
|---|---|
| `font_original`, `font_translation` | `lines.original.font.latin` and `.rtl` = `[value]` + default stack (or `["auto"]`) |
| `size_original`, `size_translation` | `.font.size`; `scale.mode = "dpi"` to keep v1 sizes exactly |
| `bold_original`, `bold_translation` | `.font.weight` = 700 or 400 |
| `color_original`, `color_translation`, `color_next` | `.color` of the three lines |
| `color_bg`, `opacity` | `container.background.color` / `.opacity` |
| `text_only` | `container.background.opacity = 0` |
| `outline`, `outline_color`, `outline_width` | `.outline` of original, translation and next (width 0 when off) |
| `shadow` | `.shadow = [{x: 2, y: 2, blur: 0, color: "#000000", opacity: 1}]` (v1's hard shadow) |
| `width` | `container.width = {unit: "px", value, fit_content: false, min_px: 0}` |
| `align` | `container.align` (left/right kept as they are) |
| `show_original`, `show_translation`, `show_next` | `.visible` |
| `rounded` | `container.corner_radius` = 8 (the Windows 11 rounded-corner size) or 0 |
| `plain_height`, positions, lock, click-through | stay in settings (not part of a template) |

v1 applied `opacity` to the whole window, text included. In v2 it fades only the box, so migrated text becomes fully opaque, which reads better. This is the one intended visual difference.

### 3.3 Contrast check

Method: WCAG 2.x contrast ratio between each line's colour (every gradient stop, after the line's opacity) and the effective background, where the box (every gradient stop, at its opacity) is composited over three extreme backdrops: white `#FFFFFF` (snow, sky, white web pages), mid grey `#808080` and black `#000000`. Required level: 4.5:1, or 3:1 for large text (at least 24 px, or 18.66 px at weight 700).

A line passes if one of these holds:

- **box**: the worst of the three backdrops meets the level, or
- **outline**: the text has an outline of at least 1 px and text vs outline is at least 7:1 (the outline then becomes the local background of every glyph edge), or
- **shadow halo (approx.)**: only for text-only lines with neither box nor outline. The soft shadows are treated as a black halo at about 60% under the glyph edges over white. This is an estimate, not a measurement, so Minimal is the one preset that is not guaranteed on pure white; Cinema or Game HUD are the choices for very bright scenes.

Karaoke sweep (34 px bold, large): unsung text at 50% opacity is 3.82:1 over white and 4.99:1 over black; the highlight colour vs unsung text is 1.60:1 over white and 2.14:1 over black, plus the glow.

## 5. Implementation notes

- **Tokens and theme**: `dualyrics/ui/tokens.py` holds the tokens; `assets/theme/dualyrics.json` is generated from them (`tokens.write_theme()`, and a test checks the file matches).
- **Fonts**: Vazirmatn is bundled as four static weights (Regular, Medium, SemiBold, Bold; about 0.5 MB) instead of the variable file, because GDI and Tk pick weights reliably only from static faces. `dualyrics/fonts.py` maps a CSS weight to the GDI family that has it ("Segoe UI Semibold", "Vazirmatn Medium", also the 31-character truncated names such as "Segoe UI Variable Text Semiligh").
- **Renderer** (`dualyrics/render.py`): as in 2.4, GDI coverage masks plus Pillow. Outlines are a round-ish dilation (alternating square and plus steps, fractional radius blended). Line layers are cached by (text, style, scale); the karaoke sweep re-composites two cached layers with a moving clip at about 30 fps. The overlay window (`dualyrics/layered.py`) is a Tk toplevel turned into a layered window that receives premultiplied BGRA frames; the box area gets a minimum alpha of 1 so text-only templates still catch the mouse (alpha 0 pixels let clicks through).
- **Acrylic** falls back to the simulated look: the DWM blur-behind accent blurs the window's whole rectangle and cannot follow per-pixel alpha, so a soft-edged rounded box would sit on a blurred rectangle.
- **Karaoke `word`** behaves like `sweep` (LRCLIB lyrics have no word timestamps). Live captions have no timing, so they are shown without the highlight.
- **Inline speaker** is drawn as its own styled label before the first line when it fits on that line; otherwise (or on a karaoke line) it goes above.
- **Preview**: a true-to-scale miniature of a 1080p screen would make the text about 6 px tall in a 348 px pane, so the preview renders at 42 % of the reference size and treats the pane as the middle 80 % of the screen (percent widths stay proportional). The contrast badges use the mean colour of the chosen backdrop. The preview column appears with Templates only, so the other sections keep the full width.
- **Sections**: the task list for v2 replaced `tab_overlay` with **Lyrics** (when to show, which lines, players) and **Monitors** (monitors, position, size, opacity, lock, click-through, virtual desktops); **Profiles** is the per-app list.
- **Virtual desktops**: the public `IVirtualDesktopManager` can only tell whether a window is on the current desktop, read a window's desktop and move one of our own windows. "All desktops" therefore follows the user (the overlay is moved to the foreground window's desktop within a second); "current desktop only" remembers the desktop where the overlay was placed and hides it elsewhere.
- **Positions** are stored per monitor (`<monitor>`) and per app profile (`<profile id>@<monitor>`) as the box centre and its top or bottom edge, plus an optional box width and text scale from resizing. v1 positions (left edge) are converted on the first start.

## 6. Open decisions

1. Public display name of the "Netflix" preset (keep, or "Streaming").
2. Bundle Vazirmatn (about 0.3 MB in the exe) or rely on installed fonts only. Recommended: bundle.
3. Default template for new installs: Cinema (works everywhere) or Game HUD (target audience). Recommended: Cinema, with Game HUD one click away in the gallery.
4. Whether to ship "adaptive backdrop" (2.4) in v2.0 or later.
